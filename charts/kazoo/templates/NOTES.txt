## 1. Make sure the images are pullable
The kazoo images default to ghcr.io/wiiaam/<image>:latest (the repo's GHCR
packages); the data plane uses official Docker Hub images. GHCR packages are
private by default, so either:
  * make the repo's kazoo-* packages public, or
  * set global.imagePullSecrets:
      kubectl create secret docker-registry ghcr-creds \
        --docker-server=ghcr.io --docker-username=<you> --docker-password=<PAT>
    and add to the chart values.
To point a component at another image: --set couchdb.image=custom:tag
(or global.imageRegistry to force ALL images incl. the official ones through
one registry).

## 2. Sensible first install (kind / single node)
  helm install {{ .Release.Name }} . \
    --set secrets.erlangCookie=<random> \
    --set secrets.rabbitPass=<pw> \
    --set secrets.couchPass=<pw> \
    --set secrets.couchSecret=<pw> \
    --set secrets.postgresPass=<pw> \
    --set secrets.masterPass=<pw>
Replace every change_me_* value -- they are shared secrets across every pod.

## 3. Checking health
  kubectl get pods -w
The data plane (couchdb/rabbitmq/postgres) must be Ready before kazoo-apps.
kazoo-apps runs kazoo-init.sh (system-db refresh, master account, fs_nodes
seed, Monster-UI app registration) on its first boot -- expect it to take
a few minutes. Verify the FS link from ecallmgr:
  kubectl exec deploy/{{ .Release.Name }}-ecallmgr -- \
    sh -c 'cd /opt/kazoo/bin && ./sup ecallmgr_fs_nodes summary'

## 4. Reaching the UI / API from a browser
kazooCore.service.type and monsterUi.service.type default to ClusterIP;
port-forward:
  kubectl port-forward svc/{{ include "kazoo.service" (dict "ctx" . "name" "monsterUi") }} 8080
  kubectl port-forward svc/{{ include "kazoo.service" (dict "ctx" . "name" "kazooCore") }} 8000
Then open http://localhost:8080 and set the Monster-UI API base to
http://localhost:8000/v2 appropriately. To actually call back into Crossbar
the Monster-UI apps must point at a host-reachable Crossbar base. This is
auto-derived when kazooCore.httpRoute is enabled (kazooCore.httpRoute.hostname
-> https?://<host>/v2); otherwise it falls back to http://localhost:8000/v2.
Pin it explicitly with --set monsterUi.crossbarApiUrl=... if you proxy
Crossbar behind your own LB.

## 5. HTTP routes (optional, Gateway API)
Each app carries its own httpRoute so you can expose them independently
(needs gateway.networking.k8s.io/v1 CRDs installed):
  helm install {{ .Release.Name }} . \
    --set kazooCore.httpRoute.enabled=true \
    --set kazooCore.httpRoute.hostname=api.example.com \
    --set kazooCore.httpRoute.tls=true \
    --set monsterUi.httpRoute.enabled=true \
    --set monsterUi.httpRoute.hostname=ui.example.com
The Crossbar base auto-derived for Monster-UI comes from
kazooCore.httpRoute.hostname (https://api.example.com/v2 here; scheme from
its tls flag). Override with --set monsterUi.crossbarApiUrl=... . Appended
HTTPRoute rules (matches/filters/backendRefs) go in <comp>.httpRoute.rules.

## 6. Phone registration (SIP) -- the advertise-IP trap
Phones MUST reach kamailio at the exact address it advertises in
Via/Contact/Record-Route, or registrations time out and in-dialog BYE/ACK die.

The component Services are generic: set <comp>.service.type +
labels/annotations + spec extras and they pass straight through to the Service
resource (LB pool selection / IP pinning / externalTrafficPolicy all live
there). Ports on the Services are fixed, so what you advertise is:

  * kamailio.service.type=LoadBalancer (recommended): give the SIP Service an
    LB IP (e.g. Cilium LB-IPAM -- pick the pool with
    kamailio.service.labels/annotations). Set kamailio.advertiseIP to the LB
    DNS name (sip.example.com); the Service keeps SIP on 5060 so Contacts
    match. Your router/firewall DNATs WAN 5060 into the LB IP.
  * For FreeSWITCH media: freeswitch.service.type=LoadBalancer +
    freeswitch.service.includeRtp=true exposes SIP 11000 + the RTP slice
    (16384-16512) on the same LB. Advertise freeswitch.publicIP (and extRtpIP
    if different) at that DNS name; DNAT WAN SIP+RTP into the LB IP.
  * Single-node lab only: kamailio.external.type=hostPort (SIP 5060 on the
    node, kamailio.advertiseIP = node LAN IP) and
    freeswitch.external.type=hostPort / hostNetwork. type: none (default) is
    in-cluster only -- phones outside cannot reach RTP.

## 7. Notes / limitations
  * This chart is single-replica: CouchDB/RabbitMQ/PostgreSQL are one-node
    StatefulSets, and more than 1 FreeSWITCH/kamailio replica is untested.
  * shared.enabled needs a ReadWriteMany volume (default storageClass may be
    RWO-only; on kind use --set shared.storageClass=<rwx-capable>).
  * ecallmgr->FreeSWITCH identity is freeswitch@freeswitch.kazoo (default
    freeswitch.nodeName); pods use hostname.subdomain DNS behind the headless
    Service named "{{ .Values.subdomain }}".
  * The kazoo apps first boot is racy against the data plane and may restart;
    the entrypoint/bootstrap are idempotent, so a couple of CrashLoopBackOff
    cycles before steady Ready is normal.
